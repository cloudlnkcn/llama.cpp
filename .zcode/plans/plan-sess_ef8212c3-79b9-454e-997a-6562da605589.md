## 目标
在 `.github/workflows/release.yml` 中新增一个 Intel SYCL（oneAPI/DPC++）release 构建 job，产物作为硬依赖接入 release 聚合 job。

## 决策（已确认）
- **硬依赖**：SYCL job 失败将阻塞整个 release 发布（与现有所有构建 job 行为一致）。
- **启用 FP16**：设置 `GGML_SYCL_F16=ON`。

## 实现方案

### 1. 新增 `ubuntu-22-sycl` job（插入位置：`ubuntu-22-openvino` job 之后，`ubuntu-vulkan` job 之前）
结构完全对齐 `ubuntu-22-openvino`（同为 Intel 工具链、Linux、运行时库打包范式），步骤如下：

1. **依赖前置**：`needs: resolve-upstream-tag` + `if: should_build`，`runs-on: ubuntu-22.04`。
2. **Clone**：从 `ggml-org/llama.cpp` checkout `resolve-upstream-tag` 给出的 tag（与所有 job 一致）。
3. **ccache**：`key: ubuntu-sycl`。
4. **Dependencies**：安装 `build-essential cmake ninja-build patchelf` + Level Zero/OpenCL 头（`level-zero-dev`、`ocl-icd-opencl-dev`）。
5. **Setup oneAPI**（新 composite action `.github/actions/linux-setup-oneapi/action.yml`）：
   - 添加 Intel oneAPI apt 仓库 + GPG key（`https://apt.repos.intel.com/intel-gpg-keys/GPG-PUB-KEY-INTEL-SW-PRODUCTS.PUB`）。
   - `apt-get install -y intel-oneapi-compiler-dpcpp-cpp intel-oneapi-runtime-dpcpp intel-oneapi-runtime-libs intel-oneapi-runtime-opencl`。
   - （固定到 oneAPI 2025.x；以 apt 元包方式安装，便于后续跟随上游。）
6. **Build**：
   ```yaml
   run: |
     source /opt/intel/oneapi/setvars.sh --force
     cmake -B build -S . \
       -DGGML_SYCL=ON \
       -DGGML_SYCL_F16=ON \
       -DCMAKE_C_COMPILER=icx \
       -DCMAKE_CXX_COMPILER=icpx \
       -DBUILD_SHARED_LIBS=ON \
       -DGGML_NATIVE=OFF \
       -DGGML_BACKEND_DL=ON \
       -DGGML_OPENMP=OFF \
       -DGGML_STATIC=OFF \
       -DLLAMA_BUILD_BORINGSSL=ON \
       -DCMAKE_BUILD_TYPE=Release \
       ${{ env.CMAKE_ARGS }}
     cmake --build build --config Release -j $(nproc)
   ```
7. **Bundle SYCL runtime libs**：从 `/opt/intel/oneapi` 下复制 `libsycl.so*`、`libpi_level_zero.so*`、`libur_loader.so*`（Unified Runtime）、`libomp.so*`、Level Zero loader（`libze_loader.so*`）到 `build/bin/`（仅拷运行时层，不拷 Intel GPU 驱动——驱动由用户系统提供，与 OpenVINO job 对 `libOpenCL.so.1` 的处理同理）。
8. **Set RPATH**：对 `build/bin/` 下所有 ELF 用 `patchelf --set-rpath '$ORIGIN'`（与 OpenVINO/Vulkan job 一致）。
9. **Validate package**：校验关键库（`libggml-sycl.so`、`libggml.so`）存在；`llama-server --version` smoke test；逐文件 `patchelf --print-rpath` 校验为 `$ORIGIN`；`ldd` 校验无缺失依赖（白名单：`libze_loader.so.1`、`libOpenCL.so.1` 等 Intel 驱动侧库视为运行时由用户提供，不计为缺失——与现有 job 对系统加载器的豁免一致）。
10. **Determine tag name**：复用 `lemonade-sdk/llama.cpp/.github/actions/get-tag-name@lemonade`。
11. **Pack artifacts**：与 OpenVINO job 相同的目录化打包范式——
    ```yaml
    pkgdir="llama-${{ steps.tag.outputs.name }}"
    mkdir -p "$pkgdir"; cp -a build/bin/. "$pkgdir"/
    tar -czf llama-bin-ubuntu-sycl-x64.tar.gz "$pkgdir"
    ```
12. **Upload artifact**：`name/path: llama-bin-ubuntu-sycl-x64.tar.gz`。

### 2. 新增 composite action `.github/actions/linux-setup-oneapi/action.yml`
封装 oneAPI apt 仓库 + 工具链安装步骤（对齐现有 `linux-setup-openvino`/`linux-setup-vulkan` 的 action 风格：`name`/`description`/`inputs`/`runs.composite`），便于复用与后续维护。

### 3. 接入 release 聚合 job（`release:` job）
- 在 `needs:` 列表中加入 `- ubuntu-22-sycl`（位于 `- ubuntu-22-openvino` 之后）。
- 产物文件名 `llama-bin-ubuntu-sycl-x64.tar.gz` 匹配现有 `*.tar.gz` 通配移动逻辑，**无需**新增移动分支。
- 在「Create or get release」的 release body 模板的 `**Linux:**` 区块中新增一行下载链接：
  ```js
  `- [Ubuntu x64 (SYCL/Intel GPU)](https://github.com/${owner}/${repo}/releases/download/${tag}/llama-${tag}-bin-ubuntu-sycl-x64.tar.gz)`,
  ```
  放在 OpenVINO 行之后。

## 不改动
- 其他 job、CMAKE_ARGS 全局 env、tag 解析/去重逻辑、上传重试逻辑均不变。
- Windows/macOS 不涉及（SYCL 后端官方仅支持 Linux/Windows oneAPI；本期按现有 release 的 Intel 工具链先做 Linux x64，与 OpenVINO 当前仅 Linux 一致）。

## 风险与缓解
- **oneAPI apt 源偶发波动**：与 OpenVINO/CUDA job 同属外部源风险，已被现有 release 的「重试可补传」机制覆盖；硬依赖策略下若 SYCL 失败会阻塞发布，符合你的选择，后续如需放宽可单独改回 best-effort。
- **oneAPI 版本**：用 apt 元包而非钉死小版本，跟随 Intel 仓库；如需固定到文档验证过的 `2025.x`，可在 action 内用 `=version` 约束。

## 验证方式
- 提交后通过手动 `workflow_dispatch` 触发一次构建，或借 PR 触发（`pull_request` 路径已含 `release.yml`）验证 SYCL job 能跑通、产物能上传、release body 含新链接。
